# 审批结果字段说明

给下游程序（渲染修复流程、统计脚本）读的接口文档。

---

## 一、文件在哪

| 文件 | 说明 |
|---|---|
| `data/results/<素材集id>.json` | **审批结果主文件**，每标记一张立即覆盖写入（原子写，不会写坏） |
| `data/results/<素材集id>.history.jsonl` | 追加式流水，每行一次操作，只增不改，用于追溯「谁什么时候改成了什么」 |
| `data/results/<素材集id>.round<N>.json` | **第 N 轮的归档**（点「归档本轮，开始新一轮」时生成），格式和主文件相同 |

`data_dir` 可以在 `config.json` 里改。素材集 id 就是配置里每个素材集的 `id`，例如 `demo_cards`、`demo_texts`。

也可以直接在界面上点导出，拿到同样内容（另存一份方便传阅）：

```
GET /api/set/<素材集id>/export?format=json&only=problem
GET /api/set/<素材集id>/export?format=csv&only=problem
GET /api/set/<素材集id>/export?format=csv&only=problem&part=annotations   # 圈注明细，一处一行
```

`only` 取值：`all`（全部）/ `reviewed`（已审）/ `problem`（问题项：打回或存疑，**或**圈过图、挂过标签、写过备注）。

---

## 二、主文件结构

```json
{
  "set_id": "demo_cards",
  "set_name": "演示·单卡对照（源A ↔ 源B）",
  "round": 2,
  "updated_at": "2026-10-01 14:05:33",
  "items": {
    "102_front.png": {
      "status": "reject",
      "tags": ["文字溢出", "术语错"],
      "note": "标题串行了，正文压到边框外",
      "annotations": [
        {
          "side": "b",
          "x": 0.269646,
          "y": 0.338213,
          "w": 0.462250,
          "h": 0.231125,
          "note": "标题与正文重叠",
          "tag": ""
        }
      ],
      "reviewed_at": "2026-10-01 14:05:33",
      "round": 2,
      "src": "18da4b9a281e5d7482801"
    }
  }
}
```

### 顶层

| 字段 | 类型 | 说明 |
|---|---|---|
| `set_id` | string | 素材集 id |
| `set_name` | string | 素材集名称 |
| `round` | int | 当前是第几轮（点「归档本轮」会 +1） |
| `updated_at` | string | 本文件最后写入时间，`YYYY-MM-DD HH:MM:SS` |
| `items` | object | **素材 id → 审批记录**。只有被操作过的素材才出现在这里；没出现的就是「未审」 |

### 每个素材的记录

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `"pass"` 通过 / `"reject"` 打回 / `"flag"` 存疑 |
| `tags` | string[] | 问题标签，取自配置里的 `tags`（也可手填） |
| `note` | string | 备注，自由文本 |
| `annotations` | object[] | 圈选区域，见下 |
| `reviewed_at` | string | 最后一次操作时间 |
| `round` | int | 这条结果是在第几轮做的 |
| `src` | string | **审批那一刻源文件的指纹**，用于判断结果是否过期，见第五节 |
| `reviewer` | string | 可选，留空 |

**素材 id 是什么**：图片素材集里就是文件名（如 `102_front.png`）；文本素材集里按配置的 `id_template` 生成（如 `card01-槽0-0`）。它是稳定的，重新渲染素材不会变，所以下游可以拿它对回文件。

### `annotations[]` 圈选区域

| 字段 | 类型 | 说明 |
|---|---|---|
| `side` | string | `"a"` 在源A（原图）上圈，`"b"` 在源B（成品）上圈 |
| `x`,`y`,`w`,`h` | float | **相对比例，取值 0~1**，以该侧图片的左上角为原点。像素坐标 = 比例 × 图片宽/高 |
| `note` | string | 这一处的问题说明 |
| `tag` | string | 可选，预留给单条圈选打标签 |

> 坐标存相对值是为了跟缩放、窗口大小、图片分辨率解耦。下游换算：
> `px = round(x * image_width)`、`py = round(y * image_height)`，
> `pw = round(w * image_width)`、`ph = round(h * image_height)`。
> 注意 `side` 决定用**哪一侧**图片的尺寸去换算——原图和成品尺寸可能不同。

## 三、CSV 格式

### 主表（`part=main`，默认）

表头固定为：

```
素材id,名称,分组,状态,问题标签,备注,圈选数量,元数据,审批时间,轮次
```

| 列 | 说明 |
|---|---|
| 素材id | 同上 |
| 名称 | 显示名 |
| 分组 | 图片按成品所在子目录、文本按元字段（如卡型） |
| 状态 | 中文：`通过` / `打回` / `存疑` / `未审` |
| 问题标签 | 多个用 `;` 分隔 |
| 备注 | 原文 |
| 圈选数量 | 整数（明细见下面的圈注明细表） |
| 元数据 | `字段=值; 字段=值` |
| 审批时间 | 同上 |
| 轮次 | 这条结果属于第几轮 |

### 圈注明细表（`part=annotations`，界面上是「CSV（圈注明细）」按钮）

**一处圈选一行**，不挤在一格里，并且同时给出百分比和像素两套坐标：

```
素材id,名称,分组,圈选序号,画在哪侧,说明,左侧占比,上边占比,宽占比,高占比,像素x,像素y,像素宽,像素高,源文件,轮次
102_front.png,102_front.png,探索卡,1,源B成品,中文标题与正文重叠,26.96%,33.82%,46.23%,23.11%,221,277,379,189,D:\...\102_front.png,2
```

像素列是用**该侧图片的实际尺寸**换算的（原图和成品尺寸可能不同，所以按 `画在哪侧` 选对应图片）；万一图片读不到，像素列留空，百分比照样可用。

两个 CSV 都带 UTF-8 BOM，Windows 上 Excel 双击打开不会乱码；用程序读的话用 `encoding="utf-8-sig"`。

## 四、history.jsonl

每行一个 JSON，只追加：

```json
{"at": "2026-09-30 04:12:10", "item": "102_front.png", "record": {"status": "reject", "...": "..."}}
{"at": "2026-09-30 04:12:20", "item": "102_front.png", "batch": true, "status": "pass", "tags": []}
```

- 单人操作：带 `record`，是操作**之后**的完整状态；`record` 为 `null` 表示撤销回未审。
- 批量操作：带 `batch: true` 和本批的 `status` / `tags`。

## 五、源文件指纹与「结果过期」

每条结果里的 `src` 是**审批那一刻源文件的指纹**（图片取成品的 mtime+size，文本取内容哈希）。
用途：你重新渲染了某张图之后，工具能立刻告诉你「这条结果是在旧图上审的」。

判断方法（就是对 `src` 和当前文件指纹做字符串比较）：

```python
import json
from pathlib import Path

data = json.loads(Path("data/results/demo_cards.json").read_text(encoding="utf-8"))

def current_stamp(path: Path) -> str:
    st = path.stat()
    return f"{st.st_mtime_ns:x}{st.st_size:x}"

for item_id, rec in data["items"].items():
    src = rec.get("src")
    if not src:
        continue                     # 老版本结果没记指纹，当作未知，不要误判
    f = Path(r"D:\素材\成品") / item_id
    if f.exists() and current_stamp(f) != src:
        print("结果已过期，需复审：", item_id)
```

几点约定：

- **没有 `src` 字段的老结果不判过期**（工具内也一样），升级后不会把你之前审的全标成过期。
- 界面上这些条目会显示成「源文件已变」，缩略图边框变虚线黄框，顶部出现提示条，
  可以一键「清除它们的结果，重新审」（清掉的是状态，原记录仍留在 `.history.jsonl`）。
- 过了期的条目一旦被重新标记，`src` 会刷新成当前指纹，过期状态自动解除。
- 图片 URL 上也带了同一个指纹（`?v=...`），所以重渲之后浏览器不会拿旧缓存图糊弄你。

## 六、分轮次

审完一批想留档、然后在新一轮里重审时：

- 界面「轮次」区点「归档本轮，开始新一轮」→ 当前结果整体移到 `<素材集id>.round<N>.json`，
  主文件清空、`round` +1、该素材集缩略图缓存一并清掉。
- 下一轮点「筛出上轮打回的」→ 从归档文件里读出上一轮所有 `reject` 的素材，直接筛出来优先复审。
- 旧的归档文件不会被自动删除，想回看随时能读。

归档文件就是「某个时刻的完整结果快照」，格式与主文件完全一致，因此上面所有读法都能直接套用。

## 七、下游怎么读（Python 示例）

```python
import json
from pathlib import Path
from PIL import Image

RESULTS = Path("data/results")          # 相对仓库根目录
RENDER  = Path(r"D:\素材\成品")
IMAGES  = Path(r"D:\素材\assets\images")

data = json.loads((RESULTS / "render_cards.json").read_text(encoding="utf-8"))

# 1) 待修复清单：打回的卡 + 问题标签
todo = {k: v for k, v in data["items"].items() if v["status"] == "reject"}
print(f"待修复 {len(todo)} 张")
for item_id, rec in list(todo.items())[:5]:
    print(item_id, rec["tags"], rec["note"])

# 2) 把圈选区域换算成源B 图上的像素框，给修图流程用
def pixel_boxes(item_id, rec, b_root=RENDER, a_root=IMAGES):
    boxes = []
    for ann in rec.get("annotations", []):
        if ann["side"] == "b":
            candidates = list(b_root.rglob(item_id))     # 源B
        else:
            candidates = [a_root / item_id]              # 源A
        if not candidates:
            continue
        with Image.open(candidates[0]) as im:
            W, H = im.size
        boxes.append({
            "file": str(candidates[0]),
            "box": [round(ann["x"] * W), round(ann["y"] * H),
                    round(ann["w"] * W), round(ann["h"] * H)],
            "note": ann.get("note", ""),
        })
    return boxes

# 3) 按问题标签汇总，看清哪类问题最多
from collections import Counter
counter = Counter(t for rec in data["items"].values() for t in rec.get("tags", []))
print(counter.most_common())

# 4) 进度统计
total = 1179
reviewed = len(data["items"])
print(f"已审 {reviewed}/{total}")
```

## 八、写回结果的接口（程序调用）

如果不想手动编辑 JSON，也可以通过 HTTP 接口写（工具运行中时）：

```http
POST /api/set/<素材集id>/review
Content-Type: application/json

{
  "key": "<素材的 URL 键>",
  "status": "pass",
  "tags": ["字体错"],
  "note": "备注",
  "annotations": [{"side": "b", "x": 0.1, "y": 0.2, "w": 0.3, "h": 0.1, "note": "说明"}]
}
```

`key` 是素材 id 的 Base64URL 编码（界面请求里用的就是它）。如果嫌麻烦，直接改结果 JSON 更省事——工具下次启动会读进来，但**运行时改文件会被内存里的状态覆盖**，所以改文件要趁工具没开。
